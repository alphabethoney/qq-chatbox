# 每日更新一个私聊，保留其他索引会话

`tools/daily_private_sync.py --config <调度配置JSON>` 依次执行：

1. 同步到独立单私聊索引（离线快照、显式 selected 验收）。
2. 验证同一 hash 向量空间及目标会话范围。
3. 确认旧目标消息 ID 不会因替换丢失。
4. 备份现有索引三个核心文件，再替换目标会话；其他会话的轮次与向量保留。

不修改人格档案、memory 或其他运行配置；不重启机器人，不推送远端。多会话目标索引应由这个合并发布入口管理，不要再把单私聊 `sync_index.py --out` 直接指向它。发布使用三文件 generation 校验和异常回滚；硬断电/强杀仍可能留下 generation 不一致，读取端会拒绝，应使用已验证备份恢复，不能声称三文件写入是跨崩溃原子事务。运行中的机器人若只在启动时加载索引，需要另行重载/重启，不能仅据磁盘更新认定服务已生效。

配置示例（路径应为绝对路径，密钥文件不能包含在共享日志中）：

```json
{
  "live_db": "<实际QQ数据库>",
  "key_file": "<已有密钥JSON>",
  "self_qq": "<本账号>",
  "conversation": "c2c:<目标>",
  "work": "<本地日志与临时目录>",
  "private_index": "<独立私聊累计索引>",
  "target_index": "<现有机器人索引>",
  "backup_root": "<索引备份目录>",
  "build_config": "<hash256构建配置>"
}
```

调度入口强制本地 hash256 和 mock LLM，清除继承的远端模型环境覆盖；密钥从本地文件读取，不写入任务参数。首次缺少已验证私聊历史时从数据库读取，不把整个多会话索引当作单私聊水位。

`--publish-only` 可在同步成功、发布失败后重试发布，不必再次解密。同步水位属于独立私聊历史；目标多会话索引的发布记录是另一提交点。二者失败与重试不能混为“全局事务”。

## Windows 任务约定

- 每日本机当地时间触发，例如 03:00；通常配置当前用户登录后运行，无需保存登录密码。
- QQ 运行、主库写入或未处理 WAL 时退出码3，跳过本轮；不会强制关闭 QQ。
- 不允许任务实例重叠；另有进程锁保护同步与发布。
- 允许错过时间后补跑时，实际执行可能晚于03:00；机器关机/用户注销时不会保证准点执行。
- 不自动唤醒电脑，不设置 SYSTEM 或管理员身份，不调整磁盘权限。
- 详细结果见 work 下 `daily-report-*.json`、sync子目录下每轮同步报告。日志不包含正文或密钥。
- 备份会占用空间，不自动删除旧备份；请定期审查和手动归档。

首次注册前先手动验收新私聊索引与其他会话不变性，再查询任务动作、触发器与状态。没有成功注册的任务不能被报告为“已定时运行”。
