## 结论与证据边界

我倾向将“越改越差”命名为“提示词补丁累积造成行为过约束，叠加检索噪声与运行状态混杂”。它可能包含提示词层面的样本过拟合，但不足以证明严格意义的过拟合，更没有模型权重训练过拟合的证据。

本文基于使用者报告的提示词版本比较、档案加载异常、低相关检索及重复实例问题进行历史分析。公开版本不保留具体人物、运行时刻、档案体积或私人语料规模。这些运行背景未经过独立服务器验证；本阶段也未修改服务器、服务、配置或索引。

本地源码与该线上状态存在差异：

- `qq_chatbot/profile.py` 的 `load_profiles` 已用 `profile_cache_key` 注册档案；`chat.py` 使用同一函数查找。无作用域旧档案还有 speaker 别名。`tests/test_chat_integration.py` 已有重启复用档案、不再调用提炼的测试。本地已具备统一键实现，不等于线上那份旧档案已能按 c2c 作用域命中；不据此否定用户实测，也不新增跨作用域兜底。
- 本地 `prompt.py` 仍含身份边界、连贯硬要求、2~3 句以及时间线规则，不能将它当成线上初版。本次保留该文件。
- 本地 persona 在生成前仍使用全部检索结果，而生成后仅把达标结果列入出处。本次修复这一明确缺口。

## 为什么规则增加后可能更不像本人

1. **目标被逐条规则挤压。** 初版主要优化“像本人、接住对话”。新增句数、结构、禁止重复、连贯及身份纪律后，同一次生成还要满足大量显式要求；模型可能偏向稳定合规的通用回答。固定 2~3 句会强迫本来一句就足够的场景补话，也会压缩需要解释的场景。这是可解释的行为机制，不能单凭文本长就认定必然变差。
2. **局部修补可能损伤其他场景。** 针对“只发口头禅”禁止简短语气回应，可能损伤亲密闲聊中自然的短答；针对某次身份误认强化边界，可能增加回避和澄清。若每次只看触发补丁的失败案例而没有留出的场景，确实可称“提示词对失败样本的过拟合”。当前没有固定评测或盲测，所以这是风险解释，尚非测得的泛化退化。
3. **输入噪声无法靠纪律彻底消除。** hash 词袋主要提供表面词形信号和可能的哈希碰撞，不理解谁说了什么。top_k 只能取排名靠前的候选，不能保证相关。用户实测的低分旧片段进入最后一条 user 消息，紧邻当前问题，容易使生成沿着片段补全；事后出处过滤不能撤回已被输入的内容。这里的“随机”应理解为对当前语义近似无关，而不是检索算法必定随机。分数也不是正确率或相关概率。
4. **时间新旧不等于事实归属或有效期。** 加入整段时间线扩大了可用背景，同时也扩大了跨人物、历史状态与当前状态混淆的机会。“以最新为准”无法替代说话人归属、事件时间和证据性质校验。较新的玩笑、传闻或计划也不一定是当前事实。
5. **几个非提示词问题使比较失去单变量条件。** 档案键不匹配时，所谓稳定人格实际上没有固定加载，现场重建和失败回退会引入不稳定；双实例会制造刷屏和重复感。脱敏可能改变指代和风格线索，但没有对照实验，不能认定它使质量下降。较早版本最好的反馈值得保留，却无法从这一串连续改动中拆出每条规则的因果贡献。

因此，初版回退是用户选择的线上基线，不是已经证明初版全场景最优。继续改动应先固定输入和运行条件，再逐项比较。

## 修改方案（按优先级）

| 优先级 | 方案 | 预期效果 | 风险与约束 |
| --- | --- | --- | --- |
| 1（本次实施） | persona 生成前按已有 `retrieval.min_score` 过滤检索片段 | 直接切断已知低分旧聊天对回复的影响，使提示词输入和出处门槛一致 | hash 分数未校准，会漏掉有用低分片段；可能降低语气素材和事实召回。保留档案、最近对话和正常生成，不加新阈值、不改索引 |
| 2 | 核验线上档案作用域与加载键，复用已验证的本地统一键方案 | 恢复稳定人格并减少重复提炼、失败退化 | 旧档案的私聊/群聊作用域可能不明确，不能直接把无作用域档案分发到全部场景。本次不动线上；本地已有实现，应先验证而非重复修补 |
| 3 | 建固定、脱敏的多轮评测集，留出未参与改词的测试场景 | 识别局部修复和整体退化，帮助比较初版与较早版 | 人工评分有偏差，mock 无法评估像本人。建议 20~30 个场景，覆盖寒暄/亲密短答、情绪回应、追问指代、事实归属、历史与现在、纠错、无证据，盲评贴题/像本人/自然长度/事实归属/连贯，各项分开计分 |
| 4 | 在固定输入下比较初版、较早版、后期版，逐条消融 | 找出真正有益的约束，保留必要边界并允许按场景长短回复 | 应先取得准确版本，不能凭时间口述重建为“原文”；同模型、采样参数、档案、检索、历史，跨版本使用同一组输入并多次生成。不要同轮变更提示词和检索 |
| 5 | 用有语义能力的 embedding 并做归属校验和分数校准 | 改善相关性和召回，减少主体混淆 | 要重建索引、增加成本，阈值不能照搬 hash 数值；应在独立评测环境完成后交用户决定，本次禁止修改 `.chatbot/` 索引 |

双实例问题按用户报告已修好，保留单实例作为后续比较的固定条件，不把重启或服务改动列为本次工作。

## 本次实现

`qq_chatbot/chat.py` 的改动仅为：把已存在的 `good = [rt for rt in retrieved if rt.score >= min_score]` 移到分身生成前，并将 `good` 传给 `build_persona_messages`。没有改动提示词、配置、top_k、索引或档案格式。

- 阈值使用已有配置，默认 0.35，等于阈值也保留，顺序不变。
- 全部低分时仍正常调用聊天模型，保留人格档案、历史和当前问题；不套用 QA 的拒答。
- 出处与 `grounded` 继续按达标结果计算；`grounded` 仅表示存在达标检索证据，不认证整段回答真实性。
- 原始检索候选仍传给 trace，便于诊断候选质量，不代表其进入生成提示词。
- 只处理检索片段入口，不能消除档案、最近对话或模型本身的事实错误。

新增 `tests/test_persona_retrieval_filter.py`，以虚构人物、固定分数和记录模型输入的离线假模型覆盖四个回归用例：

1. 混合分数时 0.16/0.30 不进入生成，0.35/0.80 保留，顺序及出处一致。
2. 全部低分时仍生成，保留档案/历史/问题，`grounded=False` 且出处为空。
3. 显式配置阈值为 0 时保留 0 分候选，证明没有硬编码新门槛。
4. QA 无证据仍提前返回，不调用模型。

这些测试验证编排契约，不能证明真人感已经提升。
