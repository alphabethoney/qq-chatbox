# 单私聊同步与离线快照

同步工具可以把一个私聊的范围贯穿导出、累计历史、索引和消息水位。本文的账号与路径均为占位符；这是一轮同步命令，定时运行需另行配置任务计划，不会自动创建系统任务或关闭 QQ。

## 命令

先正常退出保存记录的 QQ 客户端，然后运行：

```powershell
python tools/sync_index.py --live-db "<实际nt_msg.db路径>" --key-file "<本地密钥JSON文件>" --self-qq "<本账号>" --conversation "c2c:<聊天对象>" --snapshot-mode offline-copy --integrity-mode full --base-json "<已有历史JSON目录>" --work _work/private-sync --out .chatbot-private --config "<本地模型配置>"
```

密钥文件可为已有提取命令生成的 JSON 或原始十六进制密钥文件。来源由 `--live-db` 明确指定；密钥文件中的路径不是自动选择数据源的授权。不会输出密钥内容。不使用密钥文件时仍可用现有口令文件方式。

`--conversation` 目前只接受单个 `c2c:` 会话。`--self-qq` 表示本账号；`--person` 是独立的索引人物过滤，默认不要指定，以保留双方发言。`--full` 只对当前私聊范围重新读取全部历史，不扩大范围。

## 两种验收策略

| 模式 | 接受条件 |
|---|---|
| `full`（默认） | 页面认证及全库完整性检查通过 |
| `selected`（显式） | 所有非零页认证通过，目标私聊表及其所需结构完整可读，目标导出严格成功；全库错误仍保留在报告中 |

若已确认真实库含全零页面或其它会话的结构错误，且只需目标私聊，可明确选择 `--integrity-mode selected`。该模式不是“忽略错误”：首页无效、截断页、任何非零页 HMAC 失败、目标私聊结构或读取失败仍会阻止提交。

完整长度的非首页全零页可以原样保留，但没有可认证的 HMAC，因此报告会列出例外页并区分非零页认证与全页认证。目标表通过不代表整个数据库被修复。报错页号、页头保留区或格式差异不能未经验证就改写为正常页。

## 快照与在线消息

CLI 默认使用 `offline-copy`：仅 Windows 支持自动离线复制。检测到 QQ 运行或无法取得拒绝写入/删除共享的只读文件句柄时，跳过本轮，不停止 QQ、不更新索引或水位。正常退出 QQ 使主库完成检查点后再试；非空 WAL/journal 会阻止自动离线同步。

复制时检查主库与 sidecar 身份、长度和内容变化，快照放在独立临时目录，结束后仅清理本轮目录。原始库不被修改。每轮临时快照路径不同，不应改变数据库来源身份或让缓存每次全量重建。

`--snapshot-mode provided` 表示调用方已经取得不可变离线快照；工具仍检测变化，但变化检测不构成在线数据库的一致性保证。本阶段不提供 VSS，不合并真实 QQ WAL，不承诺包含只在 WAL 中的新消息。

## 状态和迁移

新私聊状态绑定来源、身份、会话、快照和验收策略。累计历史和最终语料必须只包含目标会话；消息水位仅在导出、合并、构建和发布成功后推进。

- `base-json` 只导入索引中目标会话的文件，不读取其它会话正文作为累计数据。入站 `peer_qq` 兼容本账号或发送者两种布局：真实 NTQQ 的该字段可能表示聊天对象，而非收件人；第三账号或缺失标识会拒绝。仅有聊天对象标识不能证明存档属于哪个本账号，导入外部历史前仍需调用方确认账号来源。
- 范围或策略不兼容时使用新的 `--out`；不会删除旧索引，也不自动将全范围水位缩成私聊水位。
- 从旧全范围历史迁移时，在新的输出目录运行，并把旧累计目录作为 `--base-json`，明确确认其来源账号对应。
- 已有累计而本轮无新增消息时保留历史及水位。首次没有找到目标记录时，不发布空索引覆盖现有服务。
- `--adopt-existing-history` 不能绕过会话范围不匹配。
- 失败可能留下已正确更新的解密缓存，但不能提前推进消息水位；下次从旧水位重新导出。

## 缓存、成本与报告

可加 `--decrypt-cache <独立持久目录>` 复用未变页面。缓存绑定来源身份、范围与验收器版本，策略改变需要按错误提示显式重建。详情见 [差分页解密缓存](<incremental-decryption.md>)。

空间预检需考虑加密快照、完整明文、页恢复暂存和索引。首次建立缓存或大量页面变化时可能同时暂存整库，不能把“差分解密”理解为无需完整明文空间。全库指纹与完整性检查仍有读取成本；单私聊累计合并和索引构建也仍按其全部累计历史执行。

每轮在 `--work` 下写独立 `sync-report-*.json`，区分快照、认证、全库检查、目标范围检查、导出、索引和提交结果，记录计数与耗时，不记录正文或密钥。CLI 源忙退出码为 `3`，一般同步失败为 `1`，参数错误为 `2`；`no_target` 需查看报告，不能当作已发布索引。直接调用 Python API 为兼容旧调用默认 `snapshot_mode='provided'`，自动任务建议使用明确指定参数的 CLI。源忙的跳过不能被当作成功更新。推送属于独立可选操作，不能从本地成功推断远端已加载；本轮默认不推送。

选择性导出的 SQL 与元数据扫描边界见 [选择性导出](<selective-export.md>)。本功能不是聊天记录修复工具，也不是实时监听服务。
