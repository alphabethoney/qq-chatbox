# 差分页解密缓存

本功能是增量解密的第一阶段：扫描加密页并比较指纹，只解密新增或变化的页面。它不提供自动卷快照、WAL 连续跟踪或无需扫描的增量读取。所有示例均使用占位符。

## 使用

保持加密快照路径和缓存目录固定，首次和后续使用相同命令：

```powershell
python tools/sync_index.py --live-db "<一致快照中的nt_msg.db>" --passphrase-file "<口令文件>" --base-json out/json --work _work/sync --out .chatbot --decrypt-cache _work/decrypt-cache --config chatbot.yaml
```

也可使用已有的 `--key` 参数。不传 `--decrypt-cache` 时仍使用每轮全量解密。缓存应位于持久、受访问控制的本地目录，独立于一次性工作目录；上例清理 `_work/sync` 不影响 `_work/decrypt-cache`，删除整个 `_work` 则会丢失基线并在下次重新全解。

强制重新解密缓存：

```powershell
python tools/sync_index.py --live-db "<一致快照中的nt_msg.db>" --passphrase-file "<口令文件>" --base-json out/json --work _work/sync --out .chatbot --decrypt-cache _work/decrypt-cache --rebuild-decrypt-cache --config chatbot.yaml
```

`--rebuild-decrypt-cache` 必须与 `--decrypt-cache` 一起使用。`--full` 只控制消息导出水位，补回窗口外的迟到消息；它不要求重新解密所有未变化页。必要时可以同时使用两个开关。

## 数据与提交边界

缓存维护一份明文数据库，以及加密页指纹、明文页指纹和恢复元数据。缓存不保存原始密钥或口令，但数据库与恢复信息包含明文聊天内容，不能提交仓库或作为普通日志分享。

数据库的来源路径、头部、盐值及页面布局用于识别基线；密钥与布局变化不能直接复用旧页。正常追加、修改和截短均以物理页为单位处理，包括 SQLite 的索引、空闲页和头部，不能只更新消息正文所在页。

更新顺序：

1. 持有缓存独占锁，先恢复上次未完成的页修改。
2. 验证密钥、来源身份和缓存完整性，扫描加密页，准备变更页及旧页恢复数据。
3. 将恢复记录持久化后，才原地写入明文缓存；缩短文件前保留需要恢复的旧尾页。
4. 刷盘，进行 SQLite 完整性检查，复核来源没有发生变化，再提交新页指纹与身份。
5. 在锁仍持有时供消息导出以 SQLite `mode=ro&immutable=1` 读取；读取完成后释放锁。同步工具自动为缓存导出启用 `--immutable`，普通导出不会自动获得这一假设。

若直接调用 `open_decrypted_cache`，必须在 context 内完成只读操作，不可把返回路径交给脱离锁生命周期的读写程序。明文页哈希用于检测缓存损坏；元数据与缓存目录本身需要可信访问权限，并非防御可同时修改数据库和元数据的攻击者。

已完成缓存更新与消息索引发布是两个独立提交点。缓存更新成功后，即使后续构建索引失败，也可以保留这份正确缓存；下次从未推进的消息水位重新导出。缓存数据不随 `sync_index.py --push` 传到运行机。

已有旧同步累计历史，但尚未记录源身份时，默认拒绝自动迁移，保留原水位与累计数据。确认这些历史属于同一来源后，可以在缓存命令中显式添加 `--adopt-existing-history`：保留旧累计，进行一次全量消息读取，并为新累计代记录身份。也可以选择新的 `--out` 单独建立索引。该确认不允许绕过已知的身份不匹配。

已知源身份变化时执行全量读取并开始新的累计来源，旧代保留供恢复，不自动混入新账号。显式提供的 `--base-json` 仍由调用方负责与目标账号对应。路径、头部和盐等身份字段无法识别所有同密钥同盐的旧快照恢复；发生时间倒退或补历史时仍需 `--full`。

## 资源和一致性限制

- **降低解密量，不保证降低源读取量。** 当前实现每轮读取加密主库三遍：准备页差分、应用前复核、应用后复核；复用页也会校验缓存明文，sidecar 会参与变化检测。没有变化时可以不调用页面 AES 解密，但仍有读取、哈希和 SQLite 检查成本。输出中的 `decrypted_pages` 和 `reused_pages` 是页面数量，不是耗时或读取字节量。
- **持久磁盘占用仍包含一整份明文库。** 正常更新额外保存变更页和恢复数据；首次建立、强制重建、换库或大量页面变化时可能接近全量暂存。SQLite 事务日志、页面元数据与下游索引另计，不保证固定的磁盘峰值或提速倍数。
- **只处理主库。** 本阶段不合并 WAL；尚未进入主库的消息不会被读取。需要一致的离线快照。检测到源文件或相关 sidecar 在操作期间变化会拒绝更新，但变化检测不能替代操作系统或数据库提供的一致快照机制。
- **仅覆盖当前解密布局。** 必须通过现有页面 HMAC 和 SQLite 结构检查；未知 QQ 格式不能因缓存而绕过校验。
- **下游仍有全量步骤。** 累计 JSON 合并和向量索引构建尚未因此变成增量。
- **恢复属于失败回滚。** 中断后恢复旧基线，再重新扫描本次来源；不是从任意页号继续先前解密，也不承诺硬件不遵守刷盘语义时的数据安全。
