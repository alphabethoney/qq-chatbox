# qq-chatbot 完善功能路线图（Roadmap）

> 本文档列出现有实现之上的改进方向。每条按「目标 / 现状 / 方案 / 工作量 / 验收标准」描述。
> 优先级：P0 = 直接影响核心体验，P1 = 质量与可维护性，P2 = 扩展与工程化。

---

## 优先级总览

| 编号 | 功能 | 优先级 | 预估工作量 |
|---|---|---|---|
| R1 | 增量同步（按时间戳只导新增） | P0 | 中 |
| R2 | 语义向量化（替换 hash 词袋） | P0 | 中 |
| R3 | 检索评测体系（RAG + 人格一致性） | P1 | 中 |
| R4 | 时间线记忆增强（精确时间戳 + 增量） | P1 | 中 |
| R5 | 长期记忆与记忆衰减 | P2 | 大 |
| R6 | 导出健壮性（WAL 解密 / 断点续传 / 并发） | P2 | 大 |
| R7 | 管理与可观测（日志 / 置信度 / Web） | P2 | 大 |
| R8 | 群聊精准性（成员/身份感知） | P2 | 小 |

---

## R1 增量同步（P0）

- **目标**：同步不再每次全量重导大型数据库，改为只处理新增消息。
- **现状**：`tools/sync_index.py` 解密整个库 → 全量导出 → 与 base 合并去重（msg_id）。耗时并占用较多磁盘空间，需预留明文库及中间产物所需空间。
- **方案**：
  1. 记录上次同步的 `last_msg_time`（或按 msg_id 水位线）到 `.chatbot/manifest.json`。
  2. 导出时只取 `time > last_msg_time` 的消息（SQL 层过滤，避免全量扫描）。
  3. 增量 live JSON 与现有 base 合并（保留 msg_id 去重），重建索引。
  4. 首次无水位线时退化为全量。
- **工作量**：中（改 export 增加 `--since` 过滤 + sync 记录水位线）。
- **验收**：二次同步仅处理新增，耗时与磁盘占用大幅下降；新增消息正确并入，无重复。

---

## R2 语义向量化（P0）

- **目标**：把检索从「字面/词袋相似」提升到「语义相似」。
- **现状**：`index/embeddings.py` 用 hash 词袋（本地、离线、零依赖），同义改写/口语化问法检索不到。
- **方案**：
  1. 复用已有可插拔 embedding 后端（`ollama` / `openai`），在 `build` 时把每条 turn 生成语义向量存入索引。
  2. `retrieve` 用向量余弦 + BM25 混合（现有 hybrid 已支持，仅需换 embedding 实现）。
  3. 保留 hash 作为无网络回退（配置开关）。
  4. 需处理：向量维度、持久化格式、查询时同 provider 重嵌。
- **工作量**：中。
- **验收**：同义问法（如「约饭」vs「聚餐」）能命中同一证据；离线 hash 模式仍可用。

---

## R3 检索评测体系（P1）

- **目标**：用可复现指标量化检索与生成质量。
- **现状**：仅有单元测试，无端到端评测；检索质量靠人工体感（如「上下文关联不强」）。
- **方案**：
  1. 建标注集：若干「query → 期望命中的证据（msg_id/turn）」。
  2. 计算 hit@k、MRR、召回率。
  3. 人格一致性：抽查回复的「语气相似度 / 事实真实性 / 时间线一致性」。
  4. 集成到 `tests/` 或独立 `qq_chatbot/eval/`（已有骨架 `metrics.py`）。
- **工作量**：中。
- **验收**：跑一条命令出分数；改检索参数前后可对比。

---

## R4 时间线记忆增强（P1）

- **目标**：更精确、可增量更新的时间线，彻底避免时间线冲突。
- **现状**：`profile.py` 用 LLM 按时间分桶抽样抽时间线（最多 20 条），一次性生成、无精确时间戳、无增量。
- **方案**：
  1. 事实抽取改为「带精确日期」的结构化条目（`{time, event, source_msg_id}`）。
  2. 按时间分桶逐段抽取后合并，去重冲突项（同一主题取最新）。
  3. 增量：新消息只抽取新增段的时间线，追加/覆盖旧条目。
  4. 提示词里以「当前时间」为锚点，明确标注每条时间线的可信度。
- **工作量**：中。
- **验收**：时间线含精确日期、可增量更新；回答时不会拿旧状态答新问题。

---

## R5 长期记忆与记忆衰减（P2）

- **目标**：跨会话持久记忆 + 按时间衰减。
- **现状**：会话记忆仅最近 N 轮（`session.max_turns`），无跨会话记忆。
- **方案**：会话结束后对对话做摘要存入长期记忆；检索时按时间衰减加权；定期淘汰过期记忆。
- **工作量**：大（需记忆存储、摘要、衰减、与检索融合）。
- **验收**：机器人能记住跨会话的关键信息，旧信息权重随时间下降。

---

## R6 导出健壮性（P2）

- **目标**：彻底解决 WAL、坏页、断点问题。
- **现状**：QQ 9.9.x 的 `-wal` 合并会损坏整库（已临时 `merge_wal=False` 跳过）；解密/导出无断点续传，中断需重跑。
- **方案**：
  1. 修正 `decrypt_wal` 的 WAL 帧解密/应用逻辑（核对 QQ 9.9.x 的 WAL 格式）。
  2. 解密按页流式写盘（避免整库读入内存 + 整库一次写）。
  3. 导出断点续传：记录已导会话/水位，中断后跳过已完成的。
  4. 可选并发导出（多会话并行）。
- **工作量**：大。
- **验收**：WAL 能正确合并；中断可续跑；大库内存占用可控。

---

## R7 管理与可观测（P2）

- **目标**：检索/生成过程可观测、可管理。
- **现状**：`/search`、`/cite` 已提供基础透明化，但无服务端日志聚合与置信度。
- **方案**：
  1. 记录每次检索的 query → top-K（分数）→ 最终回复，落日志。
  2. 为回复标注「有依据 / 无依据」与置信度。
  3. 可选 Web 管理界面（查看命中、调整参数、看人格档案）。
- **工作量**：大。
- **验收**：可回溯「某次回答依据了哪些证据」；参数可在线调整。

---

## R8 群聊精准性（P2）

- **目标**：群聊场景更精准。
- **现状**：`restrict_group_scope` 依赖「机器人账号与导出账号同群」，否则查不到本群记录。
- **方案**：接入群成员列表，按「提问者是否本群成员」及「@关系」做范围与置信度调整。
- **工作量**：小。
- **验收**：不同群下问答命中更准，越权检索被限制。

---

## 建议落地顺序

1. **R1 增量同步** + **R2 语义向量化**（P0，直接影响同步耗时与检索相关性）。
2. **R3 检索评测**（P1，先有度量再谈优化）。
3. **R4 时间线增强**（P1，稳固「数字分身」的事实一致性）。
4. 其余 P2 按需推进。
