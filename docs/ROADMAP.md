# qq-chatbot 功能路线图与实施状态

本文区分「已实现的行为」「合成测试覆盖」与「真实环境验收」。代码具备某个接口不等于模型效果、真实 QQ 版本兼容性或全部运行故障已验证。所有测试和示例使用虚构数据；不以私人聊天规模作为性能依据。

详细配置与命令见 [Roadmap 使用指南](<roadmap-usage.md>)。

## 状态总览

| 编号 | 功能 | 优先级 | 当前状态 | 仍需验收 |
|---|---|---|---|---|
| R1 | 时间戳增量同步 | P0 | 已实现水位线、重读窗口、累计快照和失败不推进 | 大库资源开销、窗口外迟到消息、源快照一致性 |
| R2 | 语义向量与持久化 | P0 | 已实现 hash / Ollama / OpenAI 后端、向量空间校验、可选 hash 回退 | 真实模型的同义改写效果与端点兼容性 |
| R3 | 检索与人格评测 | P1 | 已实现离线检索报告、基线对比及人工评分汇总 | 扩大标注集；不能当成自动事实认证 |
| R4 | 增量时间线 | P1 | 已实现来源校验、增量指纹、时间与状态区分、档案备份 | LLM 抽取准确率及复杂时间/冲突场景 |
| R5 | 长期记忆与衰减 | P2 | 已实现可选持久化、身份隔离、衰减、淘汰与删除 | 真实使用的召回效果；默认关闭 |
| R6 | WAL / 容错 / 恢复 | P2 | 已实现合成样本 WAL 修复与会话级导出恢复 | 真实 QQ WAL、持续写入一致性；解密续传与并发未实现 |
| R7 | 管理与可观测 | P2 | 已实现可选追踪、跨进程日志锁与令牌认证管理 API | Web 管理界面未实现；分数不代表事实概率 |
| R8 | 群聊身份与范围 | P2 | 已实现成员缓存、可选成员检查及各检索入口范围限制 | 实际 OneBot 服务端兼容性与成员变化事件 |
| R9 | 发送前脱敏 | P0 | 已实现昵称/群名/QQ号/手机/邮箱占位符替换、昵称与群名回复还原 | 旧索引需重新 build 才含群名；脱敏粒度可按需细化 |

## R1 增量同步

[同步工具](<../tools/sync_index.py>) 在成功完成导出、合并和索引构建后提交 `manifest.sync`，保存消息时间水位线、源配置和累计快照校验信息。后续读取从 `last_msg_time - overlap_seconds` 起的消息；默认重读窗口为 300 秒，最少 1 秒。按会话及消息 ID 去重，保留同秒新增消息。

首次同步、配置不兼容或 `--full` 时进行全量读取。导出不完整、校验失败或后续阶段失败时不推进水位线。源路径变化开启新数据来源，避免混入另一来源的累计快照。

可选 `--decrypt-cache <目录>` 在首次全量解密后保存明文基线和页指纹，后续只解密新增或变化页，使用持久恢复记录保护原地更新。详见 [差分页解密缓存](<incremental-decryption.md>)。该开关不改变 `--full` 的消息水位语义；同路径换库等身份变化需重新建立基线。

**限制**：未启用缓存时仍每轮全量解密；启用后仍需全库扫描和缓存校验。累计 JSON 合并及索引构建仍为全量，不是向量增量；磁盘需容纳明文缓存、页恢复数据和累计产物。超过重读窗口的迟到消息需 `--full` 补回。同步工具跳过 WAL，无法承诺读到尚未进入主库的消息；必须使用一致快照。读取端累计原始数据留在索引目录的 `.sync/`。推送只传 corpus、embeddings 和剔除 sync 状态的 manifest，不传解密缓存，也不覆盖或删除远端 profiles/memory；它不是远端服务的全局事务。

## R2 语义向量

[索引实现](<../qq_chatbot/index/store.py>) 持久化实际使用的 provider、model、dim 和向量，并校验向量数量、维度和有限数值。查询加载时检查同一向量空间；不把不同模型或 hash 与语义向量直接混用。旧索引信息不足或配置不兼容时应重建。

默认 hash 离线可用；Ollama / OpenAI 后端用于语义向量。`embedding.fallback_to_hash` 默认关闭；显式开启后，构建或查询的后端故障可切到完整的 hash 向量空间，语义索引可携带单独的 hash 备用向量。

**限制**：hash 回退会改变检索效果，不证明同义句召回能力。在线/本地模型服务的质量与兼容性需要在同一标注集上验收；本轮离线验证不访问云端服务。

## R3 可复现评测

[CLI](<../qq_chatbot/cli.py>) 的 `eval` 支持 `--demo` 虚构语料、`--dataset`、`--k`、`--output`、`--baseline`。报告包含 hit@k、recall@k、MRR 及逐样本结果；基线对比要求相同数据集指纹和兼容的评测设置。

报告记录实际 embedding provider/model/dim、语料指纹，以及每个样本查询实际使用的 embedding（可区分是否回退）；不能仅以请求配置判断所测向量空间。

`--reviews` 汇总人工的 `style`、`factuality`、`timeline` 评分，每项为 0..1，样本 `case` 唯一。它提供人工评价的统计结果，不会自动判断答案是否真实。

**限制**：内置演示集只验证评测流程。检索指标不能独立证明回答忠实度、人格一致性或真实世界事实正确性。

## R4 时间线与档案

[时间线模块](<../qq_chatbot/timeline.py>) 对来源 Turn、消息 ID 与逐字引用做校验，并用指纹增量处理新增或变更来源。条目区分消息的来源时间与原文明确表达的事件时间，保留不确定、历史、被替代、冲突和来源变更等状态。提示词以当前时间为参照，不把旧条目自动当成当前事实。

`profile --kind` 选择风格样本类型，`--conversation` 限制档案来源会话；同一人的跨群/私聊来源需要显式范围控制。档案按身份、类型、会话分别缓存，原子替换前把旧版本复制到 `profiles/history/`，不自动清理备份。

**限制**：来源校验只证明引用能对应原始记录，不证明说话内容是真的；抽取 confidence 不是事实真实性概率。没有明确日期时保留空事件时间，不把消息发送时间冒充事件发生时间。LLM 仍可能漏提或误分主题；不能承诺完全消除时间冲突。

## R5 长期记忆

[记忆存储](<../qq_chatbot/memory.py>) 每轮保存有长度上限的原文摘录，用户陈述与 bot 生成文本分字段存储。SQLite 事务支持原子持久化、重启读取及多实例/多进程并发写入。相关性乘以半衰期权重排序，读写时清除过期条目，另有 `prune()` 和按 scope/单条删除接口。

`memory.enabled` 默认关闭。CLI 还需显式 `chat --session <本地身份>`；QQ 按机器人、群/私聊、提问者及模式等构造独立 scope。`/forget` 删除当前身份和模式的长期记录并清除当前短期历史。HTTP `/chat` 无可信用户身份，不使用长期会话记忆。

**限制**：当前为提取式摘要和字面检索，无语义摘要质量保证。所有摘录明确标识非事实认证，bot 输出不是证据。记忆是本地明文数据库；删除接口不等于介质安全擦除，也不会删除原始索引或其它 scope。

## R6 导出健壮性

已有流式主库解密、结构检查及双向扫描容错导出。WAL 修复覆盖帧校验、提交边界及加密页面布局；标准 SQLite 与合成 codec 测试通过，不构成真实 QQ WAL 兼容性证明。

[大库导出工具](<../tools/export_large.py>) 已支持 `--resume`，合成恢复测试通过。首次运行即启用 checkpoint；重跑检查源 DB/WAL/journal 指纹、参数及完成会话产物 digest，源或参数不匹配时拒绝恢复，产物缺失/损坏时重新写出，坏页残缺读取不记成功。

**限制**：只跳过已完成且有效会话的序列化和写盘，仍全源哈希、扫描、解析、分桶、排序全部匹配消息；不保证更快或降低内存。解密断点续传及可选并发导出未实现。真实 QQ 版本、持续写入一致性与真实规模资源开销待验收；同步工具仍跳过 WAL。

## R7 管理与可观测

`observability.enabled` 默认关闭；启用后记录耗时、模式、证据引用摘要、各项检索分数及 grounded 标记。`include_content` 默认 false，不记录问题、答案或证据正文；显式开启才记录内容。日志按大小轮换。

HTTP 提供令牌保护的 `GET /admin/traces`、`GET /admin/retrieval` 与 `POST /admin/retrieval`。令牌来自配置或 `QQ_CHATBOT_ADMIN_TOKEN`，未配置令牌拒绝管理请求。在线调整仅影响当前进程，不写回配置，不重建向量。

HTTP 问答与管理参数更新通过锁保持配置一致。日志使用 SQLite 跨进程锁协调写入和轮换，读取时跳过损坏记录，追加时隔开不完整尾行。

**限制**：grounded 表示存在超过阈值的检索依据，不是回答事实认证；分数不是概率。未实现 Web 管理界面；日志恢复不代表损坏的内容可以还原。

## R8 群聊身份与范围

QQ 桥接缓存 OneBot 群成员列表，支持请求超时和成员变更失效。`bridge.group_member_check` 默认关闭；开启后，成员状态未知或身份不在名单中时拒绝受保护的群聊请求。

`restrict_group_scope: true` 对普通 QA、persona、档案来源、`/search`、`/kind`、显式 person/conversation 参数等入口执行本群限制。提及目标只缩小检索范围，不授权跨群。会话历史和长期记忆按提问者隔离，切换模式清理当前上下文。

**限制**：成员列表来自 OneBot 服务端，其真实性与可用性仍依赖部署；启用检查可能在缓存未就绪时拒绝首次请求。群号必须与语料中的会话标识一致；这不是其它 HTTP/CLI 入口的用户认证机制。

## R9 发送前脱敏

[脱敏模块](<../qq_chatbot/redact.py>) 在 `llm.chat()` 边界统一过滤：把语料里的真实昵称（来自 `corpus.speakers` 的显示名、`meta.conversation_titles` 的群名/会话标题与 `bridge.persona_name`）替换为可逆占位符 `〔名N〕`，QQ 号（5~11 位）、手机号、邮箱替换为不可逆占位符 `〔号码〕/〔电话〕/〔邮箱〕`。收到回复后把昵称/群名占位符还原，保证回答仍用真实称呼；QQ 号/手机/邮箱不回填，避免云端拿到真实身份。

`llm.redact` 默认开启，作用于所有 LLM 调用（人格档案、时间线、运行时问答）；本地 `ollama` 模式下数据不出门，脱敏同样生效但无额外泄露面。

**限制**：脱敏是身份匿名化，不等于内容脱敏——聊天正文本身仍会发送给云端后端。QQ 号/手机/邮箱占位符不回填，回答中若出现这些占位符会以占位符形态显示。群名/会话标题依赖语料在 `build` 时已保留（`meta.conversation_titles`）；旧索引若未含该字段，需重新 `build` 一次才会纳入脱敏名单。
