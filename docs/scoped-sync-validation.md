## 真实库联调发现与修复

1. PowerShell 7 未在 PATH 时，使用系统 Windows PowerShell 检查 QQ 进程。
2. 入站 `peer_qq` 在实际 NTQQ 库表示聊天对象，而非必然表示收件账号；兼容两种布局，第三账号标识仍拒绝。旧存档的本账号来源不能仅靠该字段证明。
3. 空 `--person` 会导致构建过滤全部消息；无人物过滤时必须省略此参数。
4. 源库存在结构错误时，默认 full 应拒绝；显式 selected 只验收目标私聊表及关联索引，报告必须区分全库失败、目标通过和零页未认证例外。

双轮同步应验证重读窗口、累计消息 ID 摘要、水位、轮次数与说话人范围。新增消息路径由合成测试覆盖。

使用 QQ 正常退出后的保护副本、本地 hash 向量、独立累计与索引目录进行验收；不以离线验证代替真实远端发布或缓存复用性能验收。应预留快照、明文、缓存及累计产物所需磁盘空间。

## 保留限制

- 不是实时监听；QQ 运行或有非空 WAL 时自动离线复制拒绝/跳过，不强制关闭客户端。
- 没有 VSS、真实 QQ WAL 合并或自动创建任务计划。
- selected 不证明全局页面所有权或空闲链完整，不是整库修复。
- 元数据/结构检查仍可能全表扫描，累计合并与索引构建仍为全量。
- 推送不是远端全局事务；本轮没有真实远端发布验收。
